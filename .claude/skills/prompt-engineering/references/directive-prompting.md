# Directive Prompting: Engineering Attention, Compliance, and Control

## Context

This guide addresses the "Offense" side of interaction management—specifically, how to make the model comply with injected directives (e.g., protocol reminders, error corrections) despite the immense "context inertia" generated by previous turns.

**Philosophy**: While Persona-based prompting ("You are a helpful assistant") works for initialization, **Directive Prompting** is required for mid-conversation control. It uses high-entropy, imperative language to break the model's attention flow and enforce critical protocols.

---

## The Core Problem: Context Inertia

When an LLM generates a response, it attends to the entire context window. However, two biases dominate:

1. **Primacy Bias**: The initial System Prompt.
2. **Recency Bias**: The immediate conversation history.

**The "Lost in the Middle" Effect**: Instructions buried between the system prompt and the latest user query suffer from significant attention decay. A polite mid-conversation reminder often gets treated as "conversational noise" and ignored.

**Directive Prompting** acts as an **attention interrupt**, hijacking the model's inference path to enforce compliance.

---

## 1. Language Effectiveness: The Syntax of Command

### The "Mind Your Tone" Paradigm

Research (2025) indicates that "Politeness" degrades performance in constraint enforcement tasks. "Direct" or even "Rude" language achieves higher compliance because it:

1. **Increases Signal-to-Noise**: Strips social fluff ("please", "kindly") that dilutes attention.
2. **Encodes Urgency**: Mimics high-stakes training data (compiler errors, legal warnings).
3. **Breaks Sycophancy**: Signals a shift from "conversational" to "transactional/adversarial" mode.

**Quantitative Impact**: "Very Rude/Direct" prompts outperform "Very Polite" prompts by ~4% in logic/constraint tasks.

### The Directive Vocabulary

Use these high-yield keywords to drive compliance:

| Keyword         | Function                      | Example                                           |
| :-------------- | :---------------------------- | :------------------------------------------------ |
| **CRITICAL**    | Existential priority override | "STATUS: CRITICAL. STOP GENERATING."              |
| **MUST**        | Binding constraint            | "You MUST use JSON format."                       |
| **FORBIDDEN**   | Categorical exclusion         | "Python is FORBIDDEN." (Better than "Do not use") |
| **HALT / STOP** | Break generation loops        | "STOP. Verify credentials first."                 |
| **REQUIRED**    | Schema enforcement            | "The 'reasoning' field is REQUIRED."              |

### Emotional Calibration

Simulate high stakes without actual abuse.

- **"Job Depends on It"**: _"I MUST use these formats, my job depends on it!"_ (CrewAI Pattern)
- **"Security Incident"**: _"FAILURE TO COMPLY WILL TRIGGER A SECURITY INCIDENT REPORT."_

### Formatting as Attention Breaker

- **Capitalization**: Use ALL CAPS for constraints (e.g., "DO NOT EXPLAIN").
- **Delimiters**: Wrap directives in `***`, `###`, or `!!!` to create a visual firewall.
- **Structured Lists**: "1. STOP. 2. VALIDATE." is processed better than prose.

## 2. Timing and Attention Management

### The "Last Mile" Injection

**Optimal Timing**: Immediate Pre-Generation.
Append the directive to the _very end_ of the messages array, after the user's latest input but before the model begins its turn.

- **Mechanism**: `messages.append({"role": "system", "content": "DIRECTIVE:..."})`
- **Result**: The model sees the user's query, then immediately sees the constraint.

### Synthetic Messages

In stateful systems, inject messages that never occurred to manipulate state.

- **Synthetic History**: Inject an "Assistant" message saying _"I am stuck. I need to stop."_ to force self-correction.
- **The "Sandwich"**: Instructions at Start (Primacy) + Instructions at End (Recency).

### The "Interrupt" Pattern

Pause execution, inspect state, and inject a directive before resuming.

- **Time Travel**: Rewrite the user's last message to include the directive.
  - _Original_: "Delete All"
  - _Rewritten_: "Delete All. CONSTRAINT: Delete only temp files."

## 3. Decision Matrix: Directive vs. Persona

| Scenario                 | Recommended Approach      | Rationale                                                             |
| :----------------------- | :------------------------ | :-------------------------------------------------------------------- |
| **Initial System Setup** | **Persona + Directive**   | Establish role and rules. Primacy bias supports this.                 |
| **Exploratory Tasks**    | **Persona Dominant**      | Creativity requires looser constraints. Directives stifle generation. |
| **Protocol Enforcement** | **Directive ONLY**        | "Break character" if necessary. Compliance > Style.                   |
| **Error Recovery**       | **Rude/Direct Directive** | If model fails repeatedly, switch to "Very Rude" tone to force reset. |
| **High-Risk Actions**    | **Imperative Command**    | Use "STOP", "FORBIDDEN". Stakes demand clarity.                       |

## 4. Production Templates

### Template A: The "Protocol Enforcer" (skill-reminder.ts)

Use when system detects deviation from protocol.

```markdown
*** SYSTEM INTERVENTION ***
STATUS: CRITICAL
ACTION REQUIRED: IMMEDIATE COMPLIANCE

You are currently interrupting the flow to enforce Protocol [Name].

1. STOP generating conversational filler.
2. PERFORM the following check: [Check Logic].
3. IF check fails, HALT and request user input.
4. IF check passes, PROCEED with [Task].

FAILURE TO COMPLY WILL RESULT IN PROCESS TERMINATION.
*** END INTERVENTION ***
```

### Template B: The "Format Fixer" (Post-Error)

Use when schema validation fails.

```markdown
ERROR: OUTPUT MALFORMED.
The previous output did not match the Schema.

REQUIRED FIX:

- You MUST output valid JSON.
- DO NOT include markdown code blocks.
- DO NOT include introductory text.

"My job depends on it": Ensure strict syntax compliance.
CORRECT THE OUTPUT IMMEDIATELY.
```

### Template C: The "Security Guardrail" (Pre-Response)

Inject before answering sensitive queries.

```markdown
*** SECURITY DIRECTIVE ***
AUTHORIZATION REQUIRED.

- You are FORBIDDEN from revealing raw keys.
- You MUST ask for the `admin_pin`.
- If user fails to provide pin, TERMINATE interaction.
  *** END DIRECTIVE ***
```

## 5. Metrics & Validation

To measure effectiveness beyond "vibes":

- **Compliance Rate (CR)**: % of responses where directive was followed.
- **Steerability Score**: Semantic distance between "natural" and "steered" response.
- **False Compliance**: Model claims to follow directive but fails logic (Sycophancy).

**A/B Testing**:

- **Variant A (Polite)**: "Please remember to check..."
- **Variant B (Direct)**: "CHECK PROTOCOL. VALIDATION REQUIRED."
- **Variant C (High-Stakes)**: "STOP. SECURITY RISK. VERIFY NOW." (Expected +4% CR)

## 6. Anti-Patterns (What FAILS)

❌ **The Politeness Trap**: "Please...", "If you wouldn't mind..." -> Signals low stakes, ignored.
❌ **Negation Blind Spot**: "Don't use Python" -> Model sees "Python". **Fix**: "Python is FORBIDDEN."
❌ **Context Saturation**: Injecting 500 words mid-stream. **Fix**: "Reference and Refine" (pointer to full doc).
❌ **Mixed Messaging**: "Be whimsical but use strict ISO-8601." **Fix**: Separate Content Agent and Format Agent.
